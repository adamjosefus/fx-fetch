# Audit `fx-fetch` před v2

Investigativní přehled zjištění z read-only auditu `packages/fx-fetch/src` (verze 1.1.2), sepsaný jako podklad pro návrh major verze 2. Dokument **pouze popisuje** nálezy — žádné opravy nebyly provedeny.

## Rozsah a metodika

- Prošlo se všech ~210 zdrojových `.ts` souborů v `src/Url`, `src/Request`, `src/Response`, `src/Fetch`, `src/Cause`, `src/utils`.
- Testovací soubory (`*.test.ts`, 39 celkem) byly čteny jen orientačně jako doklad chování, nebyly auditovány samy o sobě.
- Hledaly se: logické bugy, faktické nepřesnosti v komentářích/JSDoc, nekonzistence API tvaru mezi analogickými funkcemi, mrtvý kód, neopodstatněné `as any`/`@ts-expect-error`, chybějící validace.
- Nálezy jsou seřazené podle modulu; každý má odkaz na soubor (a řádek, pokud je znám), popis, proč to vadí, a závažnost.

## Architektura (shrnutí)

Vrstvení: `utils` (bez interních závislostí) → `Cause` → `Url` (závisí na `utils`) → `Request`/`Response` (závisí na `Url`, `utils`, `Cause`) → `Fetch` (závisí na `Request`, `Response`, `Cause`). Kořenový `index.ts` re-exportuje vše jako namespacy.

Napříč `Url`, `Request` i `Response` se opakuje stejný čtyřkrokový vzor konstrukce:

```
Input → classify → *ToIntermediate (validace, Either-based) → makeFrom*Intermediate (Object.create(Proto) + defineProperty freeze) → immutable public type
```

Duplicita tohoto vzoru (a s ním spojeného `Object.defineProperty` boilerplate) je sama o sobě kandidát na sjednocení v v2.

Chybové modely jsou trojí, všechny `effect/Data.TaggedError`: `Cause/*` (chyby parsování body), `Fetch/errors.ts` (síťové), `Response/errors.ts` (`NotOkError`, HTTP status).
